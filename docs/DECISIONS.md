# NovaCalc — Принятые решения (DECISIONS)

## D1. Почему .NET Framework 4.8
Требуется запуск на **чистой** Windows 10/11 без установки чего-либо. .NET Framework 4.8 встроен в эти системы, итоговый `NovaCalc.exe` не тащит runtime-DLL и NuGet-зависимости рантайма. Альтернатива .NET 8 self-contained дала бы файл ~70–150 МБ вместо ~150 КБ.

## D2. Почему WinForms
Разрешённый стек (C#/WinForms), минимальные требования к графике, полный контроль над безрамочным окном и Region-скруглением, предсказуемое поведение DPI через manifest. WPF тянет больше зависимостей и сложнее в однофайловой доставке; консоль не подходит под требования дизайна.

## D3. Точность: decimal как основной тип
Базовая арифметика (+ − × ÷ %, степени целых, память, Ans) выполняется на `decimal` — `0.1 + 0.2` даёт ровно `0.3`, до ~28–29 значащих цифр. Транцендентные функции (тригонометрия, log, ln, нетривиальные корни) считают на `double`, результат конвертируется обратно в `decimal` с обрезкой до 15 значащих цифр — это честный предел double и защита от «ложной точности». Форматирование вывода отдельно ограничивается настройкой «число знаков».

## D4. Парсер: рекурсивный спуск вместо shunting-yard
Уровни грамматики: выражение → аддитивные (со встроенной семантикой процентов Windows) → мультипликативные → унарные ± → степень (правоассоциативная) → постфиксные (`!`, `%`) → вызовы функций/числа/скобки/константы. Рекурсивный спуск проще поддерживает функции с несколькими аргументами (`root(x,n)`, `mod(a,b)`), константы без скобок (`pi*2`, `e^2`) и понятные сообщения об ошибках. Ошибки (деление на ноль, переполнение, domain-ошибки) — типизированные исключения `CalcException`, UI показывает их аккуратно, падений нет.

## D5. Проценты — как калькулятор Windows
Постфиксный `%` в бинарной операции трактуется относительно левого операнда: `200+10%=220`, `200-10%=180`, `200*10%=20`, `200/10%=2000`; автономно `10% = 0.1`. Логика встроена в парсер, а не «косметика строки», поэтому работает и в полных выражениях с приоритетами.

## D6. Дизайн: безопасная имитация акрила
Настоящая перфорированная прозрачность (WS_EX_LAYERED/Blur-Behind) нестабильна в WinForms на разных GPU/DPI. Решение: безрамочное окно (`FormBorderStyle=None`) + округлённая `Region` + двухступенчатый градиент + тёмная тема по умолчанию и светлая, переключение тем без перезапуска перекраской контролов. Стабильность важнее «настоящей» прозрачности. Скругление кнопок — GraphicsPath + ручные состояния hover/press.

## D7. Локализация: статичный встроенный словарь
Переводы — в `src/Localization/Strings.cs`: ключ → массив из 12 языков (en, ru, uk, kk, de, fr, es, it, pt, tr, zh, ar). Fallback всегда English (пропущенная строка покажется по-английски). При первом запуске язык определяется по `CurrentUICulture`, недоступный язык → English. Язык сохраняется в JSON-настройках и применяется мгновенно перестройкой текста контролов — без перезапуска. Никаких resx-сборок и внешних API перевода. Добавление нового языка: добавить код в `SupportedLanguages`, расширить массивы переводов и `CultureFor`.

## D8. Числа и локаль
Математический движок принимает только `.` как десятичный разделитель ввода (независимо от локали — парсер не ломается). Отображение форматируется по выбранной культуре (разделители групп, запятая/точка), но значение внутри — всегда invariant decimal. Клавиша `,` при вводе тоже принимается и нормализуется.

## D9. Хранение: JSON рядом с пользователем, без реестра
Настройки/история/курсы — простые JSON-файлы (собственный мини-парсер `MiniJson`, без NuGet). Путь: `%APPDATA%\NovaCalc`; если рядом с exe лежит `portable.flag` — папка возле exe (режим флешки). Цепочка запасных путей APPDATA → LOCALAPPDATA → TEMP и try/catch на каждой записи: read-only папка не роняет приложение.

## D10. Валюты офлайн
Стартовые курсы 8 валют (RUB, USD, EUR, CNY, KZT, BYN, GBP, JPY) встроены как значения по умолчанию и хранятся в `rates.json` с датой последнего изменения. Пользователь редактирует курсы вручную. Онлайн-обновление — отдельная кнопка, запрос только по явному нажатию, таймауты и try/catch: без сети приложение просто сообщает о недоступности.

## D11. Сборка без обязательной Visual Studio
`build.bat` пробует три пути: MSBuild (ищет VS 2022/2019/BuildTools) → `dotnet build` (ReferenceAssemblies — только build-time) → встроенный в Windows `csc.exe` из `Microsoft.NET\Framework64\v4.0.30319`. Код написан под C# версии, доступной стандартному компилятору Framework 4.x, поэтому третий путь реально работает. После сборки — автозапуск `--selftest` и копирование в `dist\`.

## D12. SelfTest как часть exe
`NovaCalc.exe --selftest` гоняет ~77 проверок без открытия GUI и возвращает код 0/1 — используется build.bat, CI и пользователем для диагностики. Это исключает отдельный тестовый проект и лишние файлы в релизе.

## D13. Однофайловый релиз
В артефакт CI и в `dist\` попадает только `NovaCalc.exe`. Иконка и manifest вкомпилированы, ресурсы — в коде. Никаких `.dll`, `.config`, README рядом.

## Компромиссы
- Имитация акрила вместо настоящей прозрачности — ради стабильности.
- 15 значащих цифр для результатов тригонометрии — физический предел double, честнее показывать меньше.
- RTL для арабского — зеркалится только порядок элементов панели, без полного RTL-движка (не усложняет интерфейс, текст читается корректно).
- Онлайн-обновление курсов отсутствует в offline-сборке по умолчанию — сеть строго опциональна.
